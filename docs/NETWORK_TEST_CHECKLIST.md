# 联网版测试清单

以下清单用于发布前验证。快速的本机联网流程可先执行：

```bash
ADMIN_PASSWORD='管理员密码' node tools/network-smoke.mjs
```

该脚本会验证账号单客户端、房间、战位、通信边界、聊天、双方就绪和管理员开局，不替代
下面的 UI、高 DPI 和异常网络人工检查。

## 专项自动化回归

- [ ] 独立账号生命周期测试（源码：`tests/test_account_room_lifecycle.py`）：
  `uv run --with-requirements server/account/requirements.txt python tests/test_account_room_lifecycle.py`
- [ ] 房间托管契约（脚本：`tools/room-hosting-contract.mjs`，需服务已启动）：
  `ADMIN_PASSWORD='管理员密码' node tools/room-hosting-contract.mjs`
- [ ] 权威房间测试（源码：`tests/test_authoritative_room.cpp`，目标：
  `authoritative_room_tests`，CTest：`GameServer.AuthoritativeRoom`）：
  `cmake --build build/debug --target authoritative_room_tests && build/debug/authoritative_room_tests --gtest_color=no`

## Docker 与账号平台

以下条目中的相对路径命令仅适用于仓库根目录源码手动部署；已安装发布包必须使用
`$HOME/wargame/current` 的绝对路径和固定 Compose 项目名。

- [ ] 在仓库根目录源码手动部署场景，从空数据卷执行
  `docker compose --project-name wargame --env-file .env -f deploy/compose.yml up -d --build`，两个健康检查均通过。
- [ ] `http://localhost:8080` 可访问，错误管理员密码被拒绝，正确密码可进入控制台。
- [ ] 创建普通联网账号；用户名重复、短密码和非法用户名被拒绝。
- [ ] 修改账号显示名、密码和启用状态后，列表与统计数字同步更新。
- [ ] 停用、改密或删除账号后，该账号已有联网会话失效。
- [ ] 同一账号第二次登录返回 `USER_ALREADY_ONLINE`，桌面端显示中文提示。
- [ ] 创建房间时指挥官数量只能为 1，其余战位数量和通信/侦察参数可保存。
- [ ] 房间创建、编辑、删除、开启准备、停止、重置和重新部署均可通过网页完成。
- [ ] 管理员在网页修改密码后现有管理会话失效，新密码可重新登录。
- [ ] `./deploy/reset-admin.sh` 可交互重置管理员密码，且不影响兵棋账号。
- [ ] 容器重启后账号、管理员密码和联网场景仍从持久卷恢复。
- [ ] 推演运行中重启 `game-server` 后，时间、HP、FSM、航点、攻击目标和双方就绪/阶段从检查点恢复。
- [ ] PVE 使用 `AI_PROVIDER=rules` 时不产生 Ollama 请求；使用 `AI_PROVIDER=auto` 且宿主机
  已执行 `ollama pull qwen3.5:2b` 时，监控页显示 `effectiveEngine=ollama` 或可解释的规则回退。
- [ ] 停止/阻断宿主机 Ollama 后，`auto` 在有限超时内回退规则，监控记录失败类别和
  `stickyRules`，推演 tick 与 WebSocket 仍保持可用。
- [ ] Compose 配置包含 `host.docker.internal` 主机映射但没有 `ollama` 服务；容器能访问宿主机
  Ollama，宿主机 `11434` 未对公网开放。
- [ ] 重复提交同一用户的同一 `commandId`（包括断线重连后）只执行一次，并返回相同结果。
- [ ] 宿主机除 `127.0.0.1:8080` 与 `127.0.0.1:8090` 外无额外服务端口暴露。

## 客户端模式与登录

- [ ] 客户端首次启动显示本地/联网模式选择，未选择时不能关闭对话框。
- [ ] 本地模式保留原有四视角、场景编辑和推演操作。
- [ ] 联网登录的服务器地址、用户名、密码错误时显示中文错误且不会进入推演页面。
- [ ] 账号登录后先选择房间，再按服务器返回的空闲战位进入；不接受客户端伪造阵营或权限。
- [ ] 双方指挥官未占用时，非指挥战位被服务器拒绝；每个战位只能同时被一个客户端占用。
- [ ] 设置面板能从本地切到联网，也能从联网切回本地。
- [ ] WebSocket 短暂中断时显示重连状态，服务恢复后自动重新认证并同步快照。
- [ ] 人为丢弃一个 delta 后，客户端停止应用后续增量并通过完整快照恢复一致状态。

## 准备阶段与权限

- [ ] 指挥官可在准备阶段部署本方单位，其他战位进入后收到部署提示并等待所属指挥官。
- [ ] 推演开始后战位锁定；网页管理员是唯一的开停、重置、重新部署和速率控制方。
- [ ] 缺失、重复或已摧毁任一方指挥所时不能提交有效开局条件。
- [ ] 红蓝双方可独立提交和取消就绪，所有客户端实时显示双方状态。
- [ ] 只有双方指挥官均就绪且场景有效时，网页“开启推演”操作才会成功。
- [ ] 任意客户端直接发送开局、暂停、调速、单步和结束消息均被服务器拒绝。

## 推演同步与视野

- [ ] 多客户端观察到的推演时间、己方位置、HP、状态和毁伤结果一致。
- [ ] 每个非指挥战位只收到本单位、侦察范围内敌情和明确共享的情报；未探测敌方不出现在网络载荷中。
- [ ] 敌方进入侦察范围后出现在对应阵营客户端，后续可见性符合既有共享侦察规则。
- [ ] 红蓝只能控制己方存活单位，猜测敌方 ID、越界坐标和不可见目标均被拒绝。
- [ ] 网页管理员可停止/重置房间；运行中客户端不能伪造全局控制。
- [ ] 指挥所被摧毁后胜负事件只出现一次，网页重置后回到准备阶段。
- [ ] 服务器重启后时间、HP、FSM、航点、攻击目标、地图标记和阶段从检查点恢复。

## 实时通信与 UI

- [ ] 各战位只能向明确指定且处于有向通信链路内的友方战位发送中文、英文和混合文本。
- [ ] 空消息不会发送，超过 500 字被限制，快速刷屏触发服务端限流提示。
- [ ] 新登录用户能看到最近聊天记录，容器重启后聊天历史按设计清空。
- [ ] 1100x720、1360x860 和高 DPI 窗口下登录、顶部栏、阵容编辑、导演控制和聊天不重叠。
- [ ] 房间选择、战位选择、部署提示、情报共享目标和推演阶段切换状态一致。
- [ ] 管理网页在常见桌面宽度下表格、弹窗、密码页无文字溢出或控件遮挡。
- [ ] 管理员可在“服务器监控”查看兵棋服务状态、连接日志和消息流；普通兵棋账号无此接口权限。
- [ ] 弱网或压力测试时，管理员监控中的累计连接、断连、重同步和服务运行时长与测试记录一致。
- [ ] 容器运维终端需要再次验证管理员密码；验证后可在 `account-web` 容器的非特权 `wargame` 用户 Shell 中执行命令，不能访问宿主机、Docker 套接字或 `game-server` 容器。

## PVE AI 运维与恢复

- [ ] 在宿主机手动执行 `ollama serve` 与 `ollama pull qwen3.5:2b`；不得通过 Compose 拉取模型或
  添加 Ollama 服务。
- [ ] 原生运行使用 `http://127.0.0.1:11434`，Compose `.env` 使用
  `http://host.docker.internal:11434`；`docker compose ... config --quiet` 展开后值正确。
- [ ] 修改 `AI_PROVIDER`、模型或超时后只重建 `game-server`，不删除命名卷；监控页显示新 provider/model。
- [ ] AI 检查点回滚前保留 `reset-room.sh` 自动生成的 `/data` 备份；重置后房间回到 preparing，
  AI 计划/失败计数清零，账号和管理员仍可登录。
- [ ] 模拟响应超大、schema 错误、模型缺失和 Compose 配置语法错误，确认服务输出可诊断失败而
  不报告误导性的“启动成功”。
